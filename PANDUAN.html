01 · Coba aplikasinya

Mulai dari sini

  1. Klik kanan file ZIP → Extract All / Ekstrak semua. Jangan membuka aplikasi langsung dari dalam ZIP.
  2. Buka folder hasil ekstrak. Klik dua kali index.html dengan Chrome atau Edge terbaru.
  3. Dashboard akan menampilkan MODE DEMO dengan 12 siswa contoh. Semua nama tersebut fiktif.
  4. Buka Terminal RFID. Dalam demo, jam simulasi sudah diatur 07.10. Klik Coba kartu siswa belum absen. Nama siswa muncul dan suara “absen berhasil” diputar.
  5. Setelah mencoba demo, ikuti pengaturan Firebase dan GitHub di bawah agar data sekolah tersimpan daring.
Paket aplikasi tidak berisi data siswa asli atau kredensial. Seluruh kode aplikasi sudah disertakan. Anda tidak perlu memasang Node.js, NPM, atau Firebase CLI.

Yang perlu disiapkan

  • Komputer/laptop, internet, dan Chrome atau Edge terbaru.
  • RFID reader USB dengan mode HID keyboard / keyboard emulation, berakhiran Enter, serta kartu yang sesuai frekuensinya.
  • Akun Google untuk Firebase dan akun GitHub.
  • Opsional: akun Meta WhatsApp Business Platform untuk pengiriman otomatis. Nomor WhatsApp pada data siswa adalah nomor penerima orang tua; pengirim adalah nomor sekolah di Meta.

02 · Penyimpanan sekolah

Pasang Firebase paket Spark

A. Buat proyek dan database

  1. Buka Firebase Console, masuk dengan akun Google, lalu buat proyek baru. Nama tampilan bebas, misalnya Absensi Al Miftah. Google Analytics tidak wajib.
  2. Gunakan paket Spark. Aplikasi ini tidak memakai Cloud Functions atau Cloud Storage.
  3. Buka Build → Firestore Database → Create database. Pilih Standard edition, ID database (default), lalu pilih lokasi yang tersedia.
  4. Mulai dengan Production mode. Selanjutnya kita mengganti Rules dengan aturan khusus aplikasi. Jangan membuka database untuk semua orang.

B. Buat akun petugas

  1. Buka Build → Authentication → Get started.
  2. Di Sign-in method, aktifkan Email/Password, lalu Save. Opsi Email link tidak diperlukan.
  3. Buka tab Users → Add user, isi email petugas dan kata sandi yang kuat. Simpan kata sandi secara pribadi.
  4. Setelah akun muncul, salin User UID. Contoh UID berbentuk rangkaian huruf/angka panjang. UID berbeda dari email dan projectId.
  5. Buka file firebase/firestore.rules dengan Notepad. Ganti GANTI_UID_ADMIN dengan UID petugas tadi, tetap di dalam tanda petik satu.
  6. Jika memakai beberapa akun admin, tulis ['UID_ADMIN_PERTAMA','UID_ADMIN_KEDUA'] pada fungsi admin().
  7. Jika WhatsApp otomatis belum dipasang, biarkan placeholder pada fungsi sender(). Ini tidak menghalangi absensi.
  8. Salin seluruh isi file aturan, buka Firestore Database → Rules, ganti isinya, lalu klik Publish.
Jangan memakai aturan allow read, write: if true;. Aplikasi harus login, dan hanya UID yang terdaftar di aturan yang bisa membuka data siswa. Akun Firebase lain tidak otomatis menjadi petugas.

C. Isi app-config.js

  1. Buka Project settings (ikon roda gigi di samping Project Overview).
  2. Pada General → Your apps, tambahkan aplikasi web dengan ikon </>. Nama boleh “Absensi Web”. Firebase Hosting tidak perlu diaktifkan.
  3. Pada tampilan konfigurasi Firebase, cari dua nilai berikut. Salin isi nilainya, bukan nama kolomnya.
NilaiDiambil dari mana?
apiKeyNilai apiKey pada konfigurasi aplikasi web Firebase.
projectIdNilai projectId pada konfigurasi web, atau Project settings → General → Project ID. Bukan “Project name”, “Project number”, atau “App ID”.

Buka app-config.js dengan Notepad. Misalnya, ubah bagian berikut dengan nilai asli Anda:

firebase: {
  apiKey: "SALIN_NILAI_APIKEY_ASLI_ANDA_DI_SINI",
  projectId: "SALIN_PROJECT_ID_ASLI_ANDA_DI_SINI",
  databaseId: "(default)"
}

Jangan menyalin contoh di atas sebagai nilai jadi. Teks di dalam tanda petik harus diganti dengan data proyek Anda. Biarkan tanda petik, koma, dan kurungnya. Simpan dengan nama app-config.js, bukan app-config.js.txt.

Konfigurasi web Firebase bukan kata sandi. Perlindungan data ada pada Authentication dan Rules. Password petugas, refresh token, private key, dan token WhatsApp tidak boleh dimasukkan ke GitHub.

D. Uji login

  1. Muat ulang aplikasi setelah menyimpan konfigurasi. Jika sudah diisi, layar login menggantikan mode demo.
  2. Masuk dengan email dan kata sandi akun petugas.
  3. Jika ditolak Rules, periksa UID. Aplikasi menampilkan UID akun yang masuk jika pembacaan awal ditolak.
  4. Buka Pengaturan → Simpan pengaturan sekali. Dokumen settings/school akan dibuat otomatis; ini juga diperlukan pengirim WhatsApp.

Batas gratis yang perlu dipahami

Firestore menyediakan kuota gratis 1 GiB data, 50.000 pembacaan/hari, 20.000 penulisan/hari, dan 20.000 penghapusan/hari. Satu proyek mendapat satu database gratis. Kuota harian direset sekitar tengah malam waktu Pasifik, bukan WIB. Lihat dokumentasi Firebase.

Periksa Firestore → Usage secara berkala. Aplikasi memuat data saat login atau tombol Perbarui ditekan, bukan membaca ulang seluruh database tiap detik. Pemindaian RFID membaca satu catatan lalu menyimpan hasil; antrean WhatsApp menambah operasi. Rekap 31 hari dapat membaca banyak dokumen. Banyak perangkat dan frekuensi pemuatan memengaruhi kuota. Paket gratis tetap memiliki batas, dan tidak menjamin penyimpanan tanpa batas sepanjang tahun.

Gunakan ekspor Excel berkala sebagai salinan laporan. Aplikasi ini belum memiliki fitur pemulihan seluruh database dari cadangan; impor Excel hanya untuk data siswa. Jangan menganggap ekspor rekap sebagai cadangan database lengkap.

03 · Alamat website

Hosting di GitHub Pages

  1. Buka GitHub dan buat repository baru, misalnya absensi-almiftah. GitHub Pages untuk repository publik tersedia pada GitHub Free.
  2. Pilih Add file → Upload files. Unggah isi folder hasil ekstrak. File index.html, app-config.js, dan folder assets harus langsung terlihat pada halaman utama repository.
  3. Seret folder assets utuh agar subfolder vendor ikut terunggah. Sertakan firebase, whatsapp, PANDUAN.html, README.md, dan .nojekyll. File contoh tidak berisi rahasia; jangan memasukkan rahasia asli ke situ.
  4. Jangan mengunggah file ZIP sebagai pengganti isi aplikasi. Jangan membungkus semua file di dalam satu folder tambahan.
  5. Klik Commit changes.
  6. Buka Settings → Pages. Pilih Source: Deploy from a branch, Branch: main, Folder: / (root), lalu Save.
  7. Tunggu proses GitHub Pages selesai. Alamat biasanya https://NAMA_AKUN.github.io/absensi-almiftah/. Gunakan alamat yang ditampilkan GitHub; nama akun dan repository mengikuti milik Anda.
  8. Di Firebase Authentication → Settings → Authorized domains, tambahkan hostname GitHub Anda, misalnya NAMA_AKUN.github.io, tanpa https:// dan tanpa nama repository.
  9. Buka alamat aplikasi, lalu login petugas. Perubahan berikutnya cukup mengubah file di repository dan Commit.
Repository publik dapat dilihat siapa pun. Jangan unggah Excel siswa, nomor WhatsApp orang tua, database asli, password, atau token Meta. Data sekolah diisi melalui aplikasi setelah login dan disimpan di Firestore.

04 · Penggunaan di sekolah

Hubungkan RFID USB dan atur jadwal

  1. Colokkan reader USB ke komputer. Pastikan perangkat memakai HID keyboard.
  2. Buka Notepad, lalu tempel kartu. ID seharusnya diketik otomatis dan kursor turun ke baris berikutnya (Enter).
  3. Jika tidak mengetik apa pun, periksa reader, kabel, kartu/frekuensi, dan mode perangkat. Reader USB serial/COM tidak langsung didukung aplikasi ini; perlu diubah ke mode keyboard atau memakai perangkat yang sesuai.
  4. Di aplikasi, buka Data siswa → Tambah siswa. Klik kolom ID RFID, tempelkan kartu, isi nama dan kelas, lalu Simpan.
  5. Buka Terminal RFID, klik kolom ID RFID agar mendapat fokus, lalu tempel kartu.
  6. Tunggu nama siswa dan konfirmasi berhasil sebelum kartu berikutnya. Bunyi dari perangkat reader sendiri belum membuktikan data tersimpan; gunakan konfirmasi aplikasi.
Aturan awalNilai

Seluruh menit jam akhir diterima: 08.00.59 masih masuk jadwal, 08.01 ditolak. Mode Otomatis memilih masuk/pulang berdasarkan jendela waktu. Memilih mode Masuk atau Pulang secara manual tetap mengikuti jadwal tersebut.

  • Pemindaian kedua untuk sesi yang sama ditolak dan tidak membuat notifikasi ganda.
  • Pulang membutuhkan catatan masuk. Jika masuk lupa, petugas membuat koreksi terlebih dahulu di Rekap.
  • Siswa yang tercatat Izin/Sakit harus dikoreksi dahulu sebelum melakukan absen RFID.
  • Internet diperlukan untuk Firebase. Jika koneksi gagal, aplikasi tidak menyatakan berhasil; sambungkan lalu tempel ulang kartu. Bila permintaan pertama ternyata sudah tersimpan, pemindaian ulang mengenali duplikat.
  • Aktifkan tanggal dan jam otomatis pada komputer. Waktu keputusan hadir/terlambat mengikuti jam komputer pada zona waktu sekolah. Aplikasi ini untuk petugas yang dipercaya, belum memakai validasi jam di server.

Nama, logo, warna, dan suara

Buka Pengaturan, ubah nama sekolah, unggah PNG/JPG/WebP, pilih warna utama, atur jam, lalu klik Simpan pengaturan. Logo diperkecil dan disimpan bersama pengaturan sehingga tidak membutuhkan Firebase Storage. Gunakan Tes suara untuk mengaktifkan suara dari tindakan pengguna; ketersediaan suara Bahasa Indonesia mengikuti sistem operasi/browser.

Beberapa komputer

Login dengan UID yang terdaftar. Pemindaian memakai prasyarat versi Firestore sehingga dua perangkat tidak menimpa absen yang sama. Perubahan dari perangkat lain muncul setelah tombol Perbarui; aplikasi tidak menyinkronkan semua data terus-menerus. Setelah menambah siswa dari komputer lain, perbarui data di terminal sebelum memindai kartu baru.

05 · Data dan laporan

Impor siswa dan unduh rekap Excel

Impor siswa

  1. Buka Data siswa → Template Excel. File .xlsx dibuat langsung oleh aplikasi.
  2. Isi sheet pertama. Header harus tetap pada baris pertama.
  3. Kolom wajib: Nama Siswa, ID RFID, Kelas. Kolom WhatsApp Orang Tua boleh kosong.
  4. ID RFID dan WhatsApp memakai format Teks (@) pada template. Jangan mengubahnya ke Angka. Pastikan ID seperti 0001230009 tidak berubah menjadi 1230009.
  5. Isi Persetujuan WA dengan YA hanya setelah persetujuan orang tua diperoleh. Tanpa YA, notifikasi otomatis tidak dibuat.
  6. Kolom Mulai Aktif boleh kosong untuk tanggal hari ini. Jika diisi, gunakan teks YYYY-MM-DD, misalnya 2026-10-16, bukan angka serial Excel.
  7. Klik Impor Excel, pilih file .xlsx atau .csv, periksa pratinjau. Semua kesalahan harus diperbaiki sebelum tombol Simpan aktif.
  8. Klik Simpan data siswa. Impor menambahkan siswa baru; ID yang sudah ada, termasuk arsip, ditolak agar tidak menimpa data.

Maksimal file 5 MB dan 5.000 siswa per impor. Format .xls lama perlu disimpan ulang menjadi .xlsx. Sheet pertama saja yang dibaca. Hindari rumus di kolom identitas. Jika format angka sebelumnya sudah menghapus nol di depan, mengubah format menjadi Teks tidak mengembalikan nol; ketik ulang ID dari kartu atau daftar sumber.

Impor disimpan dalam kelompok 100 siswa. Jika koneksi terputus, beberapa kelompok mungkin sudah tersimpan. Perbarui data dahulu, lalu impor hanya siswa yang belum ada.

Rekap lengkap

  1. Buka Rekap absensi. Pilih tanggal awal/akhir (maksimal 31 hari), kelas atau status jika diperlukan, lalu klik Tampilkan.
  2. Semua siswa aktif pada tanggal tersebut dicakup, meskipun tidak pernah menempelkan kartu.
  3. Sebelum jam masuk berakhir, siswa tanpa catatan ditandai Belum absen. Sesudah batas masuk, menjadi Alpa secara perhitungan. Tidak perlu menjalankan aplikasi terus-menerus untuk melihat Alpa pada rekap berikutnya.
  4. Catat izin/sakit lewat Koreksi, isi status serta keterangan. Koreksi manual tidak membuat notifikasi otomatis baru.
  5. Klik Unduh Excel. File memiliki sheet detail, ringkasan siswa, dan informasi periode. Filter kelas/status yang terlihat juga berlaku pada ekspor.

Definisi hitungan: kartu “Hadir tepat waktu” dan “Terlambat” terpisah. Persentase kelas = (Hadir + Terlambat) ÷ seluruh siswa kelas pada hari sekolah × 100%. Izin dan Sakit tetap dibedakan. Minggu/libur terjadwal tidak menjadi Alpa. Tanggal sebelum Mulai Aktif siswa tidak dimasukkan. Catatan kehadiran yang sudah ada tetap ditampilkan walaupun siswa diarsipkan atau tanggal kemudian ditandai libur.

Perubahan nama/kelas disimpan mulai tanggal perubahan untuk rekap selanjutnya. Pengaturan hari/jam berlaku pada perhitungan rekap; untuk masa lampau, jangan mengubah kalender tanpa memeriksa hasilnya. Fitur arsip menyimpan satu tanggal nonaktif terakhir. Jika siswa diaktifkan kembali, jeda arsip sebelumnya belum menjadi kalender nonaktif tersendiri.

06 · Opsional

Notifikasi WhatsApp orang tua

Firebase gratis bukan berarti WhatsApp otomatis gratis. Tombol WhatsApp manual tersedia tanpa integrasi API. Pengiriman otomatis memakai WhatsApp Business Platform resmi, template yang disetujui, dan akun pengirim sekolah. Meta dapat mengenakan biaya. Periksa harga resmi terbaru sebelum mengaktifkan.

Pilihan A · Kirim manual

Isi nomor orang tua di Data siswa. Buka Rekap, tampilkan tanggal, lalu klik WhatsApp pada siswa yang sudah absen. Aplikasi menampilkan pesan dan membuka WhatsApp; petugas masih menekan Kirim di WhatsApp. Ini bukan pengiriman otomatis. Di mode demo, pesan hanya dipratinjau.

Pilihan B · Otomatis melalui API resmi

Alurnya: scan berhasil → catatan dan antrean dibuat bersamaan di Firestore → Apps Script memeriksa antrean → Meta menerima template → WhatsApp mengirim kepada orang tua. Frontend GitHub tidak memegang token Meta. Firebase Functions dan Blaze tidak dipakai.

A. Siapkan Meta dan template

  1. Buka Meta for Developers. Buat/siapkan aplikasi bisnis dengan WhatsApp Cloud API dan akun WhatsApp Business Platform milik sekolah. Ikuti syarat verifikasi, penambahan nomor, izin, dan pembayaran yang diminta Meta.
  2. Di WhatsApp → API Setup, ambil Phone Number ID, versi Graph API yang sedang dipakai, serta access token yang sesuai. Untuk pemakaian sekolah, gunakan token system user dengan izin WhatsApp yang sesuai; token pengujian dapat kedaluwarsa.
  3. Nomor pengujian Meta biasanya membatasi penerima yang diizinkan. Selesaikan konfigurasi nomor produksi dan batas akun sebelum mengirim ke banyak orang tua.
  4. Di WhatsApp Manager, buat template bernama absensi_siswa, bahasa Indonesia (id), kategori utility sesuai penilaian Meta. Pilih parameter bernomor, body saja, tanpa parameter header atau tombol.
  5. Ajukan teks berikut. Jika Meta meminta revisi, pertahankan urutan tujuh parameter body. Gunakan bahasa yang lebih natural bila diperlukan; persetujuan template ditentukan Meta, bukan aplikasi.
Informasi absensi {{1}}.
Siswa: {{2}}
Kelas: {{3}}
Tanggal: {{4}}
Absensi: {{5}}
Pukul: {{6}}
Status: {{7}}
Terima kasih.

Contoh parameter saat pengajuan: SMP AL-MIFTAH KETAPANG, Nama Contoh, VII A, 2026-10-16, Masuk, 07:10:00, Hadir. Tunggu template disetujui sebelum mengaktifkan pengiriman.

B. Buat akun Firebase khusus pengirim

  1. Di Firebase Authentication → Users → Add user, buat akun baru khusus pengirim. Gunakan email yang Anda tentukan sendiri dan kata sandi kuat.
  2. Salin UID akun pengirim itu. Ganti GANTI_UID_PENGIRIM_WHATSAPP pada fungsi sender() di file Rules, lalu salin ulang aturan ke console dan Publish.
  3. Akun pengirim hanya boleh membaca antrean, pengaturan, dan satu catatan absensi untuk verifikasi, lalu memperbarui status antrean. Akun ini tidak mempunyai akses daftar siswa.

C. Pasang Apps Script

  1. Buka Google Apps Script → New project.
  2. Buka whatsapp/Kode.gs dari paket dengan Notepad. Salin seluruh kodenya untuk mengganti kode awal di editor. Klik Save.
  3. Buka Project Settings (ikon roda gigi) → Script properties → Add script property.
  4. Tambahkan setiap baris properti pada tabel berikut. Nama properti harus persis, huruf besar dan garis bawah; nilai harus diganti data asli Anda.
Nama propertiNilai yang harus Anda isi
FIREBASE_API_KEYapiKey proyek yang sama dengan aplikasi.
FIREBASE_PROJECT_IDprojectId asli, bukan nama tampilan.
FIREBASE_SENDER_EMAILEmail akun khusus pengirim yang Anda buat di Authentication.
FIREBASE_SENDER_PASSWORDKata sandi akun pengirim tersebut; bukan sandi Gmail.
META_ACCESS_TOKENAccess token WhatsApp Cloud API dari Meta.
META_PHONE_NUMBER_IDID nomor pengirim dari Meta, bukan nomor HP.
META_API_VERSIONVersi Graph API aktif dari contoh request Meta, format vANGKA.0.
META_TEMPLATE_NAMEabsensi_siswa, atau nama template Anda yang sudah disetujui dengan tujuh parameter tersebut.
META_TEMPLATE_LANGUAGEid, mengikuti kode bahasa template yang disetujui.

Semua nilai ini perlu Anda isi. Tidak ada password atau token yang sudah disediakan. Simpan properti. Jangan menaruh nilainya di file GitHub. Jika membatasi API key Firebase berdasarkan HTTP referrer browser, panggilan dari Apps Script dapat ditolak; gunakan key terpisah untuk pengirim dengan API restrictions yang sesuai. Rules tetap harus membatasi UID.

  1. Di aplikasi absensi, buka Pengaturan → Simpan pengaturan sekali agar dokumen pengaturan tersedia.
  2. Kembali ke Apps Script. Pilih fungsi cekKoneksi, klik Run, dan berikan izin pada proyek milik Anda jika diminta. Fungsi ini memeriksa Firebase tanpa mengirim WhatsApp.
  3. Jika berhasil, pilih pasangPemicu → Run. Pemicu berjalan setiap menit, dan memproses antrean pukul 06.00–14.59 pada zona waktu sekolah. Jadwal ini ditulis di Kode.gs; perlu disesuaikan jika sekolah mengubah absensi menjadi sore/malam.
  4. Tidak perlu Deploy sebagai Web App. Pemicu bekerja pada akun Google pembuat skrip. Komputer tidak harus membuka halaman Apps Script.
  5. Di Data siswa, isi nomor WhatsApp dan centang persetujuan orang tua.
  6. Di Pengaturan aplikasi, centang Buat antrean WhatsApp otomatis, lalu Simpan.
  7. Lakukan uji scan masuk pada jadwal yang berlaku, menggunakan nomor penerima yang sudah diizinkan Meta. Tunggu pemicu, lalu buka menu WhatsApp → Perbarui status.

Arti status pengiriman

StatusArti
MenungguScan tersimpan; pengirim belum mengambil antrean.
Sedang diprosesAntrean sudah dikunci oleh satu proses pengirim.
Diterima APIMeta memberi ID pesan. Belum membuktikan pesan diterima atau dibaca HP orang tua. Webhook tanda terima belum disertakan.

Antrean masuk dan pulang terpisah. Siswa tanpa nomor atau tanpa persetujuan tidak dibuatkan antrean. Koreksi manual tidak menambah antrean; antrean lama yang catatannya berubah akan dibatalkan saat diperiksa. Tidak ada mekanisme jaminan pengiriman atau retry otomatis tak terbatas. Untuk pesan gagal, perbaiki penyebabnya, pastikan pesan belum diterima, lalu gunakan tombol kirim manual di rekap bila diperlukan.

Apps Script memiliki kuota, termasuk total waktu pemicu dan URL Fetch. Akun personal saat panduan ini dibuat memiliki batas 90 menit waktu pemicu/hari dan 20.000 URL Fetch/hari. Pengirim memproses hingga 20 pesan per batch menggunakan permintaan paralel. Keterlambatan beberapa menit dapat terjadi; volume besar, limit Meta, atau kuota Google memerlukan penyesuaian. Lihat kuota Apps Script. Hapus pemicu dengan menjalankan hapusPemicu jika ingin menghentikannya.

Absen di luar jadwalPeriksa waktu komputer, zona waktu sekolah, hari sekolah, dan tanggal libur. Gunakan jam simulasi hanya di demo.
Angka nol RFID hilangGunakan template, kolom Teks, lalu ketik ulang ID dari sumber. Angka yang sudah terpotong Excel tidak dapat ditebak oleh aplikasi.
Tidak ada suaraKlik Tes suara, aktifkan suara sistem, dan gunakan Chrome/Edge. Suara Indonesia bergantung pada voice yang terpasang di sistem.
WhatsApp tidak masuk antreanAktifkan antrean otomatis sebelum scan baru. Isi nomor dan centang persetujuan. Scan ganda atau koreksi manual tidak menambah antrean.
WhatsApp terus MenungguJalankan cekKoneksi dan pasangPemicu. Pastikan pengaturan autoWhatsApp tersimpan, jam 06–14, dan tab Executions tidak menampilkan kegagalan. Periksa seluruh Script Properties.
WhatsApp Diterima API tetapi belum diterimaPeriksa delivery/error di Meta. Penerima uji harus terdaftar, akun/nomor/template harus aktif. Aplikasi ini tidak memasang webhook delivery sehingga tidak menandai “terkirim ke HP”.
Data baru dari komputer lain belum terlihatKlik Perbarui. Sistem memuat ulang atas tindakan petugas untuk menghemat kuota, bukan realtime terus-menerus.
Kode dan logika dasar diuji pada paket ini. Firebase milik sekolah, pengiriman WhatsApp sungguhan, reader USB fisik, dan tampilan pada browser/perangkat Anda perlu diuji setelah pemasangan. Jangan langsung memasukkan semua siswa sebelum uji dengan beberapa kartu berhasil.
